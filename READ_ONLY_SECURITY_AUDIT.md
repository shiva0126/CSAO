# Read-Only Security Audit

Date: July 27, 2026

## Scope

This audit covers the CSAO AWS provider, workbench capability validation path, and implemented evidence collectors used during assessment execution.

## Summary

CSAO remains an evidence-driven, non-intrusive assessment platform.

- Customer AWS activity is limited to `List*`, `Get*`, and `Describe*` operations wherever collector code performs direct AWS API calls.
- Authentication uses `sts:GetCallerIdentity` and may use `sts:AssumeRole` to obtain temporary read-only credentials.
- No implemented collector was found to require `Create*`, `Update*`, `Put*`, `Delete*`, `Modify*`, `Attach*`, `Detach*`, `Authorize*`, `Revoke*`, `Start*`, `Stop*`, `Run*`, `Execute*`, or `PassRole` against customer AWS resources.

## Direct Findings

### AWS Provider

- `core/providers/aws_provider.py`
- Uses `sts:GetCallerIdentity`
- Read-only and required for authentication and account identity

### Workbench Capability Validation

- `workbench/control_plane.py`
- Uses `sts:GetCallerIdentity`
- Uses `sts:AssumeRole` when the selected authentication mode is assume-role
- `sts:AssumeRole` is the only write-like security-sensitive operation and is limited to temporary credential acquisition

### AWS Inventory

- `modules/aws_inventory.py`
- Uses only:
  - `ec2:DescribeInstances`
  - `ec2:DescribeVpcs`
  - `ec2:DescribeSecurityGroups`
  - `s3:ListAllMyBuckets`
  - `iam:ListUsers`
  - `iam:ListRoles`
  - `lambda:ListFunctions`
  - `rds:DescribeDBInstances`

### Access Analyzer

- `modules/access_analyzer.py`
- Uses only:
  - `access-analyzer:ListAnalyzers`
  - `access-analyzer:ListFindings`

### Config Aggregator

- `modules/config_aggregator.py`
- Uses only:
  - `config:DescribeConfigurationAggregators`
  - `config:DescribeComplianceByConfigRule`
  - `config:DescribeConfigRules`
  - `config:DescribeConformancePacks`
  - `config:ListAggregateDiscoveredResources`

### Cloudsplaining

- `modules/cloudsplaining_runner.py`
- Uses AWS CLI `iam get-account-authorization-details`
- Read-only

### Prowler

- `modules/prowler_runner.py`
- Executes external Prowler tooling
- CSAO does not inject write operations into AWS through this wrapper
- Required AWS permissions must still remain read-only

### Steampipe

- `modules/steampipe_runner.py`
- Executes local Steampipe queries
- Service permissions are determined by the query pack in `queries/`
- Read-only model is preserved when queries use `List*`, `Get*`, and `Describe*`

### Cartography

- `modules/cartography_runner.py`
- Uses `cartography --update`
- Important: this writes to the analyst-owned Neo4j graph, not to customer AWS
- Customer AWS access remains read-only

### Tenable

- `modules/tenable_runner.py`
- Uses external Tenable APIs only
- No customer AWS write operations

## Conclusion

CSAO remains safe to run with a customer-provided read-only administrative role when collectors are limited to the documented least-privilege policy generated by the platform.

Residual risk:

- Third-party tools such as Prowler, Steampipe query packs, and Cartography should continue to be version-reviewed before production deployment to ensure their upstream behavior remains consistent with CSAO's read-only model.
